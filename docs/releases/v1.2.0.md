# Release v1.2.0 - Output-contract validation

Release date: 2026-10-31.

## Included

- A standard-library-only output-contract validator,
  `scripts/validate_output_contract.py`, that checks a recorded
  programmatic output record against `schemas/output-contract.schema.json`
  (the JSON form of the orchestrator's output contract in
  `skills/platform-writing-orchestrator/references/output-contract.md`).
- Platform resolution on top of the schema checks: `platform_id` must
  resolve against `config/platforms.json`, `skill_name` must be the skill
  registered for that platform, and `fact_ids_used` entries must be unique.
  Unknown keys are rejected instead of silently ignored.
- A synthetic bundled example, `examples/output-contract.example.json`,
  plus regression fixtures under `tests/fixtures/` (valid, unknown
  platform, and unknown key cases) with nine new unit tests; the test
  suite grows from 11 to 20 tests.
- The repository validator now also requires the v1.2.0 release notes,
  the output-contract validator, and its schema.

This closes roadmap issue #1 ("Add optional output-contract validation
command").

## Scope unchanged

- The skills still do not log in, upload, publish, operate accounts, or
  verify user-provided facts independently.
- The validator checks record structure and platform registration only;
  it does not judge editorial quality or platform outcomes.

## Integrity

Run against the release checkout:

```
python scripts/build_manifest.py
python scripts/validate_repository.py
python -m unittest discover -s tests
python scripts/validate_fact_packet.py
python scripts/validate_output_contract.py
```

All five commands are expected to pass.
